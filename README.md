## Період і фільтри
 
- Дані про платежі є з 05.04.2024, про сесії всіх користувачів — з 19.04.2024. Реєстрації є з 2013 року.

- Фільтр дати працює за датою реєстрації: він обирає, яких користувачів дивимось. Осі графіків показують, коли ці користувачі реєструвалися, платили та заходили в застосунок.
- Фільтри «Дата реєстрації», «Платформа», «Країна» застосовано до всіх аркушів. Клік на країну на мапі також фільтрує весь дашборд.
  
## Метрики та чому вони обрані
 
| Категорія | Метрика | Чому |
|---|---|---|
| Acquisition | Нові користувачі (Count Distinct `user_id`), мапа країн | Скільки людей приходить і звідки |
| Engagement | Медіанна тривалість сесії | Чи користуються застосунком насправді, а не лише реєструються |
| Monetization | Виручка (Sum), платники (Count Distinct), ARPPU, топ-10 країн за виручкою | Скільки грошей приносить продукт і де саме |
| Зведення | Воронка: реєстрація -> сесія -> оплата | Де втрачаємо користувачів |
 
- **Медіана, а не середнє, для сесій.** Розподіл тривалості скошений, тому середнє викривлене в бік скосу.
- **ARPPU, а не середній чек.** Один користувач може платити кілька разів; ARPPU (виручка / кількість платників) показує цінність клієнта.
- **Агрегації.** Користувачі завжди рахуються через Count Distinct, щоб relationships не дали подвійного рахунку.
  
## Рішення щодо візуалізацій
 
- **Line chart** для динаміки по тижнях (реєстрації, виручка, тривалість сесії).
- **Bar chart** для порівняння країн за виручкою. Топ-10 визначається через `RANK(SUM(amount_usd))` як фільтр, а не через Top N: табличне обчислення застосовується після всіх фільтрів, тому десятка завжди правильна для обраних даних.
- **Мапа** для географії нових користувачів (Acquisition). Топ-10 показує географію виручки (Monetization), тож вони не дублюють одне одного.
- **Воронка** допомагає зрозуміти на якому кроці найбільше втрачаються користувачі. Акцентний помаранчевий колір виділяє крок з найбільшою втратою.
- **BAN** вгорі показують підсумки за обраний період.
- **Заголовки графіків динамічні**: показують зміну за останній повний тиждень (week over week) і оновлюються разом із фільтрами. Останній тиждень у даних неповний, тому порівнюються два останні повні тижні.
